# 代码审查报告 · 听力刷题系统

审查对象：`app_template_v2.html`（635 行单文件前端）、`launcher.py`（74 行）、`MainActivity.java`（72 行）、`bank.json`
审查时间：2026-11-06
结论：**没有发现可被远程利用的漏洞**（题库内嵌、无网络、无用户输入回传），但有 6 处性能问题、7 处安全/健壮性问题、1 处数据缺陷，已全部修复并验证。

---

## 一、性能问题

| # | 位置 | 问题 | 为什么是问题 | 处理 |
|---|---|---|---|---|
| P1 | `render()` 562–569 | 每次点选项都 `app.innerHTML = html` 全量重建，并强制 `window.scrollTo(0,0)` | 单题页只有 4 个选项，代价可忽略；但**连做页一屏 4 题 16 个选项**，选一个就整页重建 + 跳回顶部，用户刚翻到的位置直接丢失。这是本次改造必须先解决的 | 选答走 `paintCard / paintFocus / updateHUD` 局部打补丁；单题判分走 `renderKeep()` 保留 `pageYOffset` |
| P2 | `byUid()` 391 | 线性查找，且在 `viewResult()` 的 `forEach` 里被调用 | `141 × 141 ≈ 2 万`次比较，当前无感；一旦题库扩到千题级就是 O(n²) 卡顿源头 | 建 `MAP[uid]` 索引，O(1) |
| P3 | `viewResult()` 505–515 | 在**渲染函数里**写 `localStorage` 并 `times+1` | 渲染函数有副作用：结果页只要被重绘一次（回退、窗口变化触发的重渲染），完成次数就多记一次，数据会虚高 | 持久化移到 `finish()`，一次会话只写一次 |
| P4 | CSS 133 | `animation:rise` 写在 `.opt` 基础类上 | 每次判分重绘，所有选项重新播放入场动画；连做页 16 个选项 × 26ms 延迟 = 最长 416ms 的"闪烁" | 改成 `.opts.anim .opt`，只在切换答题单元时挂 `anim` |
| P5 | 全局 | 全量 `innerHTML` 重建导致文本无法选中、WebView2 上有可见闪白 | 阅读长选项时想划词会失败 | 选答路径改为 DOM 补丁；整页重绘只发生在换屏 |
| P6 | `S` 状态 | `picked`、`groupShown` 两个字段从未被读取 | 死代码，误导后续维护（看代码以为是状态机的一部分） | 删除，状态收敛为 `blocks / bi / answers / submitted / orders` |

> 补充：`byUid` 之外，`viewResult()` 里 `S.queue.forEach(... byUid ...)` 与错题列表二次遍历是同一次 O(n²) 的两个来源，改索引后一并消失。

## 二、安全与健壮性

| # | 位置 | 风险 | 等级 | 处理 |
|---|---|---|---|---|
| S1 | `esc()` 494–496 | 只转义 `& < >`，**没转义 `"` `'`** | 中 | 题库目前是可信的内嵌 JSON，且渲染位置都是文本节点，所以今天不构成 XSS。但只要题目内容改成从外部导入，落进 `data-*` 属性就能闭合引号注入。已补齐五个字符 |
| S2 | `<head>` | 没有 CSP | 中 | 加 `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data:` —— 内联脚本仍需 `unsafe-inline`（单文件应用的固有限制），但**外部脚本、外链请求、eval 全部被禁**，注入面大幅收窄 |
| S3 | `load()` 321 | `JSON.parse(localStorage)` 后不做类型校验 | 低 | 存档被改成 `{"set1":{"best":"x"}}` 时 `Math.max("x", 3)` 得到 `NaN`，首页百分比变成 `NaN%`。已加 `num()` 白名单化重建 |
| S4 | `launcher.py` 20–26 | 本地 HTTP 服务**不校验 Host**，任何路径都返回同一份 html | 低 | 理论上可被 DNS rebinding 让外部页面读到本地内容（内容本身不敏感，但属于不该开的口子）。已加 `Host` 白名单（127.0.0.1 / localhost）+ `X-Content-Type-Options: nosniff` + `Referrer-Policy: no-referrer`，`/favicon` 返回 204 |
| S5 | `MainActivity` 27–28 | `setAllowContentAccess(true)`、未显式关闭 file URL 跨域读取；`allowBackup=true` | 低 | 已改 `setAllowContentAccess(false)`，显式 `setAllowFileAccessFromFileURLs(false)` / `setAllowUniversalAccessFromFileURLs(false)` / `setJavaScriptCanOpenWindowsAutomatically(false)`；manifest 加 `allowBackup=false`、`usesCleartextTraffic=false` |
| S6 | `debug.keystore` | 自签调试证书，密码 `android`，随工程目录存放 | 提示 | 本地安装够用；**若将来要上应用商店或对外分发，必须换私有 release keystore**，否则任何人可签同名包覆盖安装 |
| S7 | viewport 第 5 行 | `maximum-scale=1` 禁止缩放 | 低 | 属于可访问性问题（视力不佳的用户无法放大）。已移除；安卓端仍由 `setSupportZoom(false)` 控制，不影响防误触 |

## 三、数据缺陷（审查中额外发现）

解析器 `build_data.py` 的中英切分规则有一个系统性漏洞：只按"第一个汉字"切。

| 原始文本 | 旧结果 | 问题 |
|---|---|---|
| `A)  $20. 20美元。` | en=`$20. 20` / zh=`美元。` | 数字跑到英文里，中文丢了数字 |
| `A)  225 volt. 225伏。` | en=`225 volt. 225` / zh=`伏。` | 同上 |
| `A)  Emma. 《爱玛》。` | en=`Emma. 《` / zh=`爱玛》。` | 全角书名号不是汉字，切在括号内部 |
| `D)  OpenAI Gym. OpenAI Gym（AI测试平台）。` | en=`OpenAI Gym. OpenAI Gym（AI` / zh=`测试平台）。` | 中文段落里重复的英文名被切走 |

命中 **12 道题、40 个选项**（第 1 套 Q5/Q17/Q18、第 2 套 Q2/Q3/Q15/Q23、第 3 套 Q14、第 4 套 Q24、第 5 套 Q9/Q21、第 6 套 Q15）。
这些选项在界面上会显示成 `$20. 20`、`OpenAI Gym（AI` 这种半截文本。

已修：切分边界扩展为「汉字 **或** 全角标点」；中文以 `（《` 开头时把前面重复的英文名归回中文；英文尾部 `[.?!] 数字` 且中文不以数字开头时，把数字移回中文。重建后扫描 `en` 中的全角标点与粘连数字均为 0，141 题数量不变；选项层面只有这 12 题变动，另有 20 条妙招文本随之更新（其中 10 条是模板文案本身已经改过、`bank.json` 没跟着重建的旧文案，属于同步修正）。

## 四、没能验证的部分（如实说明）

1. **apk 仍未真机验证**。本机没有安卓设备也没有模拟器，只做了静态校验：`aapt2 dump badging` 包名/版本/SDK/应用名/图标全部正确，`apksigner verify` 证书链正常，12 个条目、`zipfile.testzip()` 通过、内嵌 html 与交付 html 的 MD5 一致。WebView 版本差异导致的 CSS 表现仍属未知。
2. **exe 已实机验证**：窗口标题「听力刷题 · 连做版」、470×880 逻辑像素（125% 缩放下 587×1100），截图确认首页渲染正常，退出无残留进程。
3. ~~妙招按题型套模板~~ → 已重写为「答案串记」：长对话/短文把 3~4 个答案串成一句带题号的话，短对话给单句钩子，141 条全部重写并有机器校验（每条必须包含正确选项的核心词，平均 30 字）。文案里不再出现选项字母，乱序时天然指不错。

## 五、改造后的架构变化

```
旧：queue = [uid, uid, ...]        一题一屏，i 指向当前题
新：blocks = [{uids:[...]}, ...]   一个单元 = 1 题（Section A）或 3~4 题（同篇）
    bi 指向当前单元
    answers[uid] = {key:'C', letter:'B'}   key=原始选项键，letter=界面显示字母
    submitted[bi] = true                 连做单元提交后锁定
    orders[uid] = ['B','A','D','C']      选项乱序的显示顺序，一次会话内固定
```

`key` / `letter` 分离是选项乱序能成立的关键：判分永远比 `key === q.answer`，界面永远显示 `letter`，两者通过 `orders` 映射。串记文案不写选项字母，直接写答案内容，所以乱序时不存在"指错字母"的问题（`tipL / tipR` 那套机制已随旧文案一起退役，产物从 158 KB 降到 132 KB）。

底部按钮的语义也修正了：原先提交后是「返回上一级（回首页）」，现在是「上一题（回上一屏）」，第一屏置灰；退出练习走左上角返回箭头。上一屏只能重看解析、不能改答案，这与"选完即判分"的既有规则一致。
